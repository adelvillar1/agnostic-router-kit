# TROUBLESHOOTING

One remediation line per known runtime failure class, newest last. Housekeeping
rule (CLAUDE.md): a new runtime failure gets a line here in the wave that
learned about it.

- **Env-var shadowing reads the wrong store.** A shell carrying
  `AGNOSTIC_ROUTER_KIT_HOME` (or a stale one) silently points kit commands and
  probes at another home — the symptom is always "my data is gone/empty."
  Remediation: `echo $AGNOSTIC_ROUTER_KIT_HOME` before diagnosing; the probes
  set it per-spawn on purpose, never inherit it.
- **Probe port collisions.** Each probe owns a fixed 127.0.0.1 port
  (8396/8399/…) — running two probes concurrently fails with EADDRINUSE, not
  with a real assertion. Remediation: run them sequentially (`npm test` since
  2026-10-07 enforces it).
- **Memory-store hand-edit loss.** `memory/memory.jsonl` is regenerated by
  atomic whole-file writes; a hand edit survives only until the next save, and
  a malformed line is skipped silently by design. Remediation: mutate through
  `kit memory`, the MCP server, or the routes — never the file.
- **GLiNER HTTP 425 cold start.** The fastino judge leg 425s when the sys1
  encoder is cold; the router's 150s keep-warm ping exists to prevent it.
  Remediation: check the keep-warm ping in the router log before blaming the
  judge or the roster.
- **launchctl lies about the service.** `launchctl list` can show a label as
  loaded while the process is dead, and bootstrap can need a retry after
  bootout. Remediation: trust only `lib/service.mjs`'s "verified running"
  (a real `/healthz` answer) — never the launchctl listing.
- **`kit apply --dry-run` reports every key unresolved from a bare shell**
  (found 2026-10-07). The dry-run resolves `apiKeyEnv` names against the
  process environment, not the runtime `.env`, so a shell without the keys
  shows `✗ … no key (…unresolved)` for every provider. Remediation: verify
  roster edits by a before/after dry-run comparison — identical output means
  the edit is behavior-neutral; do not expect green.
- **Chat `/run` bounced every name** (fixed 2026-10-07). `startRun` read the
  workflow registry — an array of objects — with `Object.keys()`, so the
  "Available" list was `/0 /1 /2` and `includes(name)` never matched. Root
  cause: the duplicated `workflows` key pair in `/api/state` (later key won)
  hid the shape. Remediation: the registry is an array — `.map(w => w.name)`;
  the shape assertions in probe-chat-surface (section S) guard it.
